# spo-mojo

A from-scratch implementation of **SPO** (Sequential Monte Carlo Policy
Optimisation, Macfarlane et al., NeurIPS 2024) in [Mojo](https://www.modular.com/mojo),
with hand-written GPU kernels.

Written during a research internship (PRe) at the **LIASD, Université Paris 8**. The
goal was not to reuse a framework but to build the algorithm down to the kernels, in
order to measure what removing the search tree actually buys and costs on an
accelerator.

Mojo 1.0.0b1 has no automatic differentiation and no learning ecosystem: only
`std.mojopkg` and `layout.mojopkg`. Every backward pass here was derived by hand,
then checked twice — by finite differences, and against JAX's autodiff on stored
golden tensors.

## What is in here

| directory | what it holds |
|---|---|
| `ops/` | primitive kernels: reductions, scan, softmax, RNG, buffers |
| `systems/spo/` | the SMC core: particles, weighting, resampling, readout, search |
| `networks/` | actor, critic, linear layers, Adam, the equation-11 loss |
| `envs/` | tic-tac-toe on device, plus a toy chain for unit tests |
| `rl_utils/` | replay buffer and multi-step returns |
| `bench/` | the measurement bench and the three-way comparison |
| `demos/` | runnable end-to-end programs, including the full training loop |
| `tests/` | the test suite and its golden generators |

About 17,500 lines of Mojo and 1,800 of Python (the golden generators, which run
JAX).

## Requirements

- **Mojo 1.0.0b1** — the wrapper expects it under `~/.pixi/bin`
- an **NVIDIA GPU** — developed and measured on an RTX 3050 Ti Laptop
- Python with JAX only if you want to regenerate the golden tensors

## Running it

```bash
./run.sh demos/train_spo.mojo        # the full EM loop: search, actor, critic
./run.sh demos/demo_tictactoe.mojo   # watch the planner play
./run.sh bench/compare.mojo          # the three-way comparison
```

`ASSERTS=1` switches on the kernels' `debug_assert` preconditions, which also report
the offending block and thread:

```bash
ASSERTS=1 ./run.sh tests/test_scan.mojo
```

## Tests

```bash
bash tests/run_all.sh
```

30 test files, 172 assertions, all on GPU. The suite covers the kernels against
hand-computed values, the backward passes against JAX goldens, and the search's
behaviour end to end.

The golden tensors are generated by `tests/golden/gen/*.py`, which run the same
computation in JAX. One detail matters there: JAX is forced to
`jax_default_matmul_precision="highest"`, because in TF32 the *reference* comes out
less precise than the kernel it is meant to verify.

## Results

Tic-tac-toe against a uniform random opponent, both seats, averaged unweighted. The
ceiling is computed by recursion over all reachable positions, not estimated.

| implementation | budget | 1st seat | 2nd seat | average | losses (%) |
|---|---|---|---|---|---|
| *exact ceiling* | — | *0.9974* | *0.9624* | *0.9799* | *0.21* |
| MCTS-Mojo (CPU) | 1,000 sim. | 0.9942 | 0.9580 | 0.9761 | 0.00 |
| SPO-Mojo (GPU) | 128 part. | 0.9965 ± 0.0007 | 0.9533 ± 0.0038 | 0.9749 | 1.80 |
| SPO-Stoix (JAX) | 128 part. | 0.9951 ± 0.0008 | 0.9416 ± 0.0036 | 0.9684 | 2.41 |

The ± are standard deviations over five complete training runs, which is a different
uncertainty from the sampling interval. Raw measurements are in
`results/bench_comparison.csv`.

The three implementations sit within 0.0022 of one another when they open, and
within 0.0164 when they answer: **the second seat is the only one that separates
them**, and the ranking even inverts there. A single-seat setup would have measured
a saturated regime where nothing shows.

## How this was validated

Equivalence with the reference implementation was **established, not asserted**: a
paired sweep over four axes in both seats, 48 comparisons, of which 44 agree to
within 3σ.

Building that protocol turned up a defect in the reference implementation, where the
search's particles shared the environment's pseudo-random generator and therefore
saw the upcoming transition leak through. It was reported upstream.

Three habits made the difference, and they are worth more than any single figure:

- **an impossible result is the best detector there is** — a score above an exact
  ceiling is not a good result, it is proof of a leak; but the ceiling has to have
  been computed first;
- **a score does not explain itself** — it says how much is lost, never why; an
  instrument that classifies the *kind* of failure answers in one pass what three
  measurement campaigns cannot;
- **a guard must be seen triggering** — one that cannot fire looks exactly like one
  that has never needed to.
